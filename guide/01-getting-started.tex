\section{Accounts and access}\label{app:start:access}
\paragraph{Overleaf project.} \emph{We} create an Overleaf project for your semester's work from this template, so that you get the features of our Overleaf Pro subscription. Ask us for it. The template is the current BME template, modified to the TDK form requirements (\cref{app:tdk:form}); check that it still matches the current call.

\paragraph{Paper repository.} \emph{We} connect the Overleaf project to a new GitHub repository with Overleaf's GitHub integration. Only the owner of the Overleaf project can use this Pro feature, and only with a fresh repository, so we create it and add you. Clone it to your machine: you can then compile locally, use every GitHub feature, and work with agent-based AI tools on it (\cref{app:code:ai}). Overleaf and GitHub stay in sync through the GitHub dialog in Overleaf's menu.

\paragraph{Code repository.} \emph{You} create the repository for your code from our template repository and add both of us. The paper repository is included in it, so one clone holds everything.
\advisortodo{Link the code repository template once it exists, and decide where notes and drawings live: a notes folder in the code repository or a separate notes repository.}

\paragraph{Zotero group.} \emph{We} add you to our Zotero group, where we collect the literature of the topic. \emph{You} install \href{https://www.zotero.org/}{Zotero} with its browser connector, save every source you read into the group library, and export the collection to \texttt{bib/references.bib} (the Better BibTeX plugin can keep the file up to date automatically).
\advisortodo{Add the Zotero group link, and confirm the export setup (Better BibTeX auto-export into the paper repository).}

\paragraph{GitHub Student Developer Pack.} Apply for the free \href{https://education.github.com/pack}{GitHub Student Developer Pack} with your \texttt{@edu.bme.hu} address; it includes GitHub Pro and GitHub Copilot.

\paragraph{Share it with your advisors.} In the Teams calendar, add your advisors' calendars: \emph{Add calendar}, type their name, add them. Ask them to give you permission to see their calendar, and share yours with them, so we can find a weekly slot (\cref{app:consult}).

\paragraph{Keeping calendars in sync.} We recommend \href{https://reclaim.ai/}{Reclaim.ai} to manage your calendar. You will likely run into permission issues with the university account; if so, \href{https://www.outlookgooglecalendarsync.com/}{Outlook Google Calendar Sync} is a workaround.

\section{Development environment}\label{app:start:env}
\paragraph{Operating system.} Use Linux on bare metal if you can. We recommend \href{https://omarchy.org/}{Omarchy}, an easy-to-use distribution set up for development; ask Martin for his setup. Ubuntu and Pop!\_OS are good options too. Omarchy has a built-in Windows virtual machine; dual boot if you occasionally need Windows on bare metal. Use the Windows Subsystem for Linux (WSL) only as a last resort, if you really have to use Windows every day for a pressing reason, such as video editing.

\paragraph{Virtual machine.} We can give you a virtual machine with 8 cores and 16\,GB of memory in the BME cloud. \advisortodo{link bme cloud}Use it to host your editor and repositories remotely, and to run AI agents that keep working while your laptop is closed. Reach it through SSH, RDP, VS Code Remote, or Tailscale, or run Claude Code, Codex, T3 Code or GitKraken Kepler on it directly.

\paragraph{Workspace layout.} Keep one clone of the code repository, with the paper repository inside it (\cref{app:code:github}), on your machine or on the VM. Open it in one editor window with the \LaTeX{} build and an AI agent working in the same folder, so that code, paper and notes are edited, versioned and searched together.
\advisortodo{Draft for the empty \enquote{Munkakörnyezet elrendezése} note; confirm or rewrite.}
